## Tailor the presentation, not the experience

Generic AI resume tools can turn a job requirement into a candidate claim.
CVTailor instead starts from your master profile and evidence-linked skills bank.
It selects relevant facts, makes gaps visible, and validates the draft outside the
LLM before document generation. Your profile is your attestation, not an external
background check; human review remains essential.

### Three steps

1. **Add your facts.** Maintain experience, projects and skill levels in one profile.
2. **Analyze an offer.** Paste a description or fetch one selected public job URL;
   inspect requirements, evidence and gaps.
3. **Review and export.** Generate a tailored draft, check warnings and confirm
   the summary when required, then save PDF, DOCX or offline HTML/HTML + CSS ZIP.

### Core features

- **Evidence-backed matching:** separates required qualifications from benefits,
  responsibilities and role fit, with source references and review warnings.
- **Truth Lock:** independent Python validation checks source facts, skills and
  proficiency; new AI drafts use full validation.
- **Local or cloud AI:** use Ollama, Gemini, or deterministic mock mode without an API key.
- **Two resume themes:** Modern Sidebar and ATS Classic, with export/layout checks;
  ATS compatibility varies by recruitment system.
- **An editable workflow:** browser editing, saved versions, comparison and History.
  [Custom CV / AI Editor](docs/custom-cv-editor.md) also works without a job offer.
- **Bounded automation:** a [batch API](docs/batch-api.md) handles explicitly supplied
  URLs; this is not a job crawler or an automatic application sender.

## What Truth Lock does (and does not do)

With full validation, generated claims are checked against source IDs and eligible
skills. Unsupported bullets can be replaced with source wording; unknown skills
are removed. Project work must not become commercial employment, and Basic or
learning-level knowledge must not become expertise.

**Fictional example** ([executable regression](tests/test_fact_validator.py)):

| Input | Result with full Truth Lock |
|---|---|
| Source: “Automated a verified operational workflow with Python.” | The documented employment fact remains available. |
| Draft: “Invented Kubernetes achievement”, citing that Python fact | Unsupported wording is replaced by the actual source sentence. |
| Draft skill: Kubernetes, absent from the profile | Removed, with a warning—not added to the profile. |

This is a deterministic validator example, not a live-model quality benchmark.
Truth Lock is **not a guarantee against all hallucinations**. Semantic summary
review can be wrong; non-source summaries require explicit confirmation before
web export. An owner can deliberately relax validation for a
[manually authored saved CV](docs/safe-manual-cv-edits.md); manual additions do not
become verified facts or alter the master profile.

## AI providers

| Provider | Use | Data boundary |
|---|---|---|
| **Ollama** | Local structured generation and analysis | Use a trusted local endpoint; disable cloud fallback for local-only AI processing. |
| **Gemini** | Direct Google API | Sends job text and candidate analysis facts to Google; requires your API key. |
| **Mock** | Deterministic onboarding and tests | No model calls; not a demonstration of LLM quality. |
| **n8n** | Optional [webhook integration](docs/n8n-setup.md) | Data handling depends on your external workflow. |

Ollama/Gemini routing includes bounded operation budgets and configurable fallback.
The fallback setting matters for privacy; selecting Ollama alone does not prove
that cloud fallback is disabled. See [provider details](REFERENCE.md#ai-providers-and-fallback-behavior).

## Quick Start: try with fictional data

On a **fresh Linux checkout**, with Docker Engine, Compose v2+ and Python 3
(standard library only for initialization):

```bash
git clone https://github.com/Rafalbanas/ai-resume-tailoring-platform.git
cd ai-resume-tailoring-platform
python3 scripts/init_demo.py
docker compose up -d --build
curl --fail http://127.0.0.1:8000/health
```

Open **http://127.0.0.1:8000**, then read `APP_USERNAME` and `APP_PASSWORD` from
your local `.env` privately. Initialization generates independent random secrets,
uses Alex Example's fictional profile, and disables AI fallback. It refuses to
overwrite existing configuration or account state. **This is mock mode**, not a
public demo. Initial image/browser downloads can take longer than five minutes.

Compose is the **alternative local/standalone path**, not a replacement for K3s.
It uses Linux host networking; do not assume these commands work unchanged on
Docker Desktop. Read the [full Quick Start and troubleshooting](docs/quickstart.md)
for platform limits, shutdown, real AI and safe handling of personal data.

## Architecture

```mermaid
flowchart LR
    UI[Browser: desktop / mobile] --> API[FastAPI + authentication / CSRF]
    API --> JOB[Job extraction + requirement validation]
    PROFILE[Profile + skills evidence] --> RET[Local BM25 fact retrieval]
    JOB --> RET
    RET --> AI[Ollama / Gemini provider router]
    AI --> TRUTH[Python Truth Lock + summary review]
    PROFILE --> TRUTH
    TRUTH --> WORKERS[Isolated document workers]
    WORKERS --> OUT[PDF / DOCX / offline HTML]
    TRUTH --> HISTORY[Private application history]
    K3S[Kubernetes / K3s: PVCs, RBAC, backups] -. hosts .-> API
    K3S -. isolates .-> WORKERS
```

The [architecture guide](docs/architecture.md), [retrieval design](docs/rag.md)
and [processing boundaries](docs/processing-security.md) describe the implementation.
CI checks contracts, security regressions, document layout and full/split Docker
images. Results depend on the revision and environment; the CI badge is the live
status, not a claim that every deployment is verified.

## Deployment

- **Kubernetes / K3s:** the existing production architecture includes persistent
  account storage, separate processing services, RBAC, reverse-proxy/TLS integration,
  backups, monitoring and digest-pinned delivery with rollback. Start with the
  [K3s production guide](docs/kubernetes-production.md); use the separate
  [Kubernetes lab](docs/kubernetes-lab.md) for practice.
- **Docker Compose:** alternative standalone Linux installation using API,
  document and browser images; only the API mounts account data.
  [Deployment guide](docs/deployment.md) · [runtime images](docs/runtime-images.md).
- **Local Python:** contributor environment and checks in [CONTRIBUTING.md](CONTRIBUTING.md).

**Maintainers:** pushes/merges to `main` trigger the configured production CD
workflow. Opening a PR does not deploy; review deployment impact before merging.

## Security, privacy and limitations

- Built for **owner-managed self-hosting**, not anonymous multi-tenant SaaS.
  The optional separate demo account is an application boundary, not an OS sandbox.
- Argon2id authentication, revocable sessions, CSRF checks, URL/SSRF defenses and
  resource budgets reduce risk; they are not a security guarantee.
- Local inference is not encryption at rest. Profiles, generated documents and
  backups contain personal data. Control access, retention and backup storage.
- Fetching public offers contacts their sites. Gemini, cloud fallback and external
  n8n workflows have their own data boundaries.
- Extraction can fail on protected job sites; paste the description instead.
  Review every claim and rendered document. Match assessments are not hiring odds.
- PDF/HTML and DOCX layout differ; offline A4 HTML can scroll horizontally on mobile.
  See [accessibility status](ACCESSIBILITY.md) and [export limitations](docs/offline-html-export.md).

Read [SECURITY.md](SECURITY.md) and report vulnerabilities privately, not in public issues.
