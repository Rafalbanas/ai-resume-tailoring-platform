# Batch quality boundaries

The batch API accepts up to 50 input URLs, still processed sequentially. The
64 KiB file limit, authentication, CSRF, SSRF checks, per-offer deadlines, queue,
daily AI budgets and storage quotas are unchanged. One failed offer does not
stop subsequent offers. This is not an unlimited scraping or parallel-inference
mode, nor a mechanism for sending applications to employers.

## Qualification and evidence checks

Explicit prior/hands-on experience and multi-adjective Polish qualification phrases
cannot disappear into context or responsibilities. Bare technology tags still
require semantic interpretation; a preceding heading alone is not authoritative.
The indexed model schema constrains explicit condition dispositions;
independent source validation rejects incomplete or misclassified coverage.
Clear company self-descriptions under organization headings remain context;
calendar years such as a company's presence since 1996 are not career durations.
Unknown semantic cases still require model interpretation and may remain blocked.

Named-scope ceilings also inspect the literal source, not only the model's short
capability title. GitHub Actions CI/CD does not establish Azure DevOps, AD user
administration does not establish SSO, VMware/VPS use does not establish Azure,
and unit/API tests or ML regression models do not establish performance/load
testing. A partial match is not a full confirmation of a compound requirement.
Examples/alternatives are not turned into cumulative product requirements.
Documented Salesforce support-case handling can establish generic ticketing work
when Zendesk is merely an example; it does not establish actual Zendesk use.

These are bounded safeguards for documented scopes, not a complete semantic
proof system for every product or profession. Unverified candidate qualifications
are never invented to improve match levels or export counts.

## Export consistency and remaining review

An analysis explicitly marked unreliable cannot export automatically in a batch.
The existing owner's manual export/review workflow remains available; this gate
does not remove the owner's control over a factual CV when a match report is uncertain.
Layout fitting is
followed by the same canonical presentation preparation used by both renderers,
before exact-text summary review and persistence. PDF, DOCX and saved resume JSON
therefore use the same final content, rather than saving a pre-cleanup summary.
Existing staged/atomic publication and quota checks remain in place.

Source-built support summaries longer than 500 characters try the existing
compact source composition; complete clauses and their citations are retained,
never sliced mid-sentence. Optional skill suffixes no longer expand generated
headlines past 100 characters; genuine source role names are not truncated.

No owner approval is generated by these checks. Required summary confirmation,
factual/provenance validation and layout checks remain active. Successful batch
iteration does not mean every CV is complete, suitable for its role, or ready to
send without owner judgment. No automated tool can guarantee that for arbitrary
model-generated CVs. Inspect per-item results, not just the parent `completed`.

Changes affect future runs/exports. Stored CVs, prior reports, profile facts and
confirmation records are not migrated, overwritten or mass-approved. A rejected
old analysis needs a fresh analysis under the corrected pipeline, not an approval
click or a larger context window. There are no new dependencies or AI stages.

Regression tests use fictional profiles and mocked providers, including a full
50-item orchestration with an isolated failure. An offline, read-only replay of
previous reports can test detection without regenerating or changing user data;
it is not proof that an unexecuted future live model run will succeed.
